# 前端代码书写与维护

本文件用于 QeePHP 项目的前端视图，通用流程、增量维护和注释维护要求沿用主文件；以下仅补充前端专属规则。

## 基础规范

基础写法参考 [MDN JavaScript 指南](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Code_style_guide/JavaScript)、[MDN HTML 指南](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Code_style_guide/HTML) 和 [MDN 通用代码指南](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Code_style_guide)，本文件只补充个人偏好和项目维护约束。涉及具体写法且项目无约定时，按需查阅对应章节。

这些指南面向 MDN 示例代码，仅参考适用的代码规则；文档宏、示例展示和英文注释要求不适用于项目代码。项目兼容范围、既有技术栈及下文约定优先，不因 MDN 示例偏好现代语法、原生 API 或 Prettier 而重写已有实现或新增工具。

## 修改前确认

- 核对页面入口、模板、脚本加载顺序、事件入口和接口调用方，确认浏览器兼容范围、构建方式及已有组件。
- 沿用项目已有的原生 JavaScript、jQuery、Layui 或其他框架，以及目录、组件、请求封装和响应协议。不为局部需求新增框架、依赖或构建步骤。
- 数据或行为缺失时，沿接口响应、服务端输出、页面状态和渲染逐层检查，不因问题出现在页面就只修改前端。

## JavaScript 流程与数据

- 前端主流程按「读取输入、校验、准备数据、执行操作、更新状态、反馈结果」展开。
- 区分 DOM 元素、jQuery 对象和业务数据，不让同一变量承载不同含义。
- 已有旧语法代码只在本次修改需要时调整。新增 `?.`、`??`、箭头函数、模块语法或浏览器 API 前核对运行环境。
- 接口与表单类型不一致时，在明确边界归一后比较。区分缺值、空字符串、零、`false` 和空数组，不用 `value || defaultValue` 覆盖有效值。
- ID 按接口约定处理；可能超过安全整数范围或带前导零的标识保留为字符串。数字转换须检查有效性和业务范围，不将无效输入转换为零后继续提交。
- 使用对象和数组保持已有数据协议；数组类型用 `Array.isArray()` 判断。修改共享对象、缓存或组件数据前确认影响范围，不为局部计算无意改变原始数据。

## 事件、DOM 与页面状态

- 选择器限定在实际页面或组件容器内；动态节点按现有方式使用事件委托。初始化须避免重复绑定，重新渲染或关闭组件时清理本次创建的监听、定时器和请求。
- jQuery 解绑只针对本次绑定的处理函数或事件命名空间，不用无范围的 `.off()` 清除其他功能。仅在确需阻止默认行为或冒泡时调用对应方法，不机械添加 `return false`。
- 页面状态有明确的数据来源，避免 DOM、隐藏字段和多个变量各自维护同一份状态。切换记录或账号时检查当前选择、编辑内容、加载状态和缓存是否需要更新。
- 筛选结果、勾选集合、当前页和操作范围分别按业务定义处理。不能因选项暂时不可见就擅自取消其选择，也不能让局部操作扩大到全量。
- 确需生成 HTML 时检查动态内容的转义或清理，不将接口文本直接拼入 HTML、属性或事件代码。
- 沿用组件更新 API，只刷新必要区域；确认组件重绘是否改变筛选、焦点、滚动和选择状态。连续输入或大列表确有重复开销时再采用防抖、节流或批量更新。

## 请求与异步操作

- 沿用已有请求封装、认证信息、CSRF 处理和错误反馈方式；保持请求方法、参数名及响应结构，不在前端擅自补造业务成功结果。
- 区分网络失败、HTTP 错误、响应解析失败和业务失败。使用 `fetch()` 时核对 HTTP 状态；请求完成不代表业务完成，以实际响应和任务状态判断。
- 保存、提交等操作按业务需要防止重复触发；成功、失败和取消均恢复相应加载状态。反馈可操作的错误，避免空 `catch`、只打印日志或失败后仍显示成功。
- 搜索、切换详情等可能交错返回的请求，使用取消请求、请求序号或当前对象校验防止旧响应覆盖新状态。旧请求结束时也不能清除新请求的加载状态。
- 不因超时或断网自动重试可能产生副作用的操作；按已有幂等约定或查询接口确认结果。批量结果保留成功、失败和未确认项，不把部分成功显示为全部完成。

## HTML 与表单

- 按用途选择标签：导航使用链接，操作使用按钮，表格用于表格数据。保持有效嵌套和唯一 `id`，不新增可用原生元素表达的点击 `div`。
- 表单控件提供关联的 `label` 或适当的可访问名称；按钮明确 `type="button"` 或 `type="submit"`。业务操作集中在实际提交入口，避免点击处理和表单提交重复执行。
- 区分 `name`、`id`、`value`、`checked`、`selected` 和 `disabled` 的作用。修改提交逻辑时检查禁用控件、多选项及未勾选项的实际序列化结果。
- 沿用组件结构、样式类和现有图标资源；不为局部排版新增全局样式或大量行内样式。新增样式限定作用范围，不把视觉调整扩展为页面重写。
- 图标按钮提供可访问名称；装饰图像使用空 `alt`，信息图像提供有意义的替代文本。新增交互保留键盘操作和可见焦点，弹窗关闭后按组件约定恢复焦点。
- 前端校验和隐藏按钮用于交互反馈，服务端仍须验证输入、权限和操作范围。不能把页面不可见或按钮禁用当作权限控制。

## PHP 模板与输出边界

- 模板负责展示和轻量条件，不把查询、复杂计算或外部接口调用塞入 HTML。页面专用脚本可沿用现有位置，不为缩短模板强制拆文件。
- 根据输出位置分别处理 HTML 文本、HTML 属性、URL 和 JavaScript 数据；优先复用项目已有转义与序列化工具，确认默认行为，避免重复编码。
- PHP 数据进入 JavaScript 时使用项目兼容的 JSON 编码方式，不手动拼接引号、反斜线或换行。内联 `<script>` 中还须处理 `</script>` 等可提前结束标签的内容；JSON 放入 HTML 属性时另按属性上下文转义。
- `data-*` 属性读取后按约定转换类型；PHP 空数组、对象、`null` 和布尔值的输出保持与消费端一致。不把所有数据都强制转成字符串。
- URL 参数使用适当的 URL 编码或 URL API；外部提供的链接检查允许的协议。HTML 转义不能代替 URL 协议检查或脚本数据序列化。

## 排版、注释与交付

- 优先沿用项目已有格式配置和附近一致写法；无约定时缩进默认用 Tab，JavaScript 字符串用单引号、语句保留分号。不要将这些默认偏好覆盖到已有工具配置。
- 多行对象的同级键值对各占一行，结束括号对齐；短而清楚的内层结构可保留单行，不递归拆开所有内容。无项目约定时，多行对象和数组末项不加逗号。
- 可复用函数或输入、返回值较复杂的方法，按实际行为用 JSDoc 说明参数、返回值和副作用；简单事件回调不机械补齐标签。
- 纯 JavaScript 语法检查不能证明浏览器兼容或交互正确；PHP 混合模板须结合 PHP 语法检查和实际渲染结果检查，替换模板片段后的检查只报告为辅助证据。
- 根据改动验证相关正常与失败流程，必要时检查重复操作、切换对象、筛选选择和键盘行为。
